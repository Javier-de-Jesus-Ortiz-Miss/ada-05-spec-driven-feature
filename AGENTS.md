# Agent Instructions

## Project Rules

- Read `REQUIREMENTS.md` and `SPEC.md` before implementing.
- Read `ARCHITECTURE.md` before architectural changes and follow `TASKS.md`.
- Prefer small, focused changes. Do not invent business requirements.
- Do not modify `REQUIREMENTS.md` or `SPEC.md` to make tests pass.
- Do not delete or weaken tests. Justify any new dependency.
- Work on one task at a time and report files, verification and unresolved issues.

## Validation

- Run `pytest` before and after changes when tests exist.
- Add tests for new behavior. Stop and ask for clarification if requirements conflict.
- Report changed files and test results.

## Definition of Done

- Relevant tests pass and acceptance criteria are covered.
- No unrelated files are changed.
- Documentation reflects final behavior.
